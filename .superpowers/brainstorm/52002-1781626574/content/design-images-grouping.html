Variant Option Images & Grouping

Adding image support to first type's options — fits naturally into inline arrays

Updated variantTypeDefs — with image on options
variantTypeDefs: array [
id: string (auto)
label: text, required // "loại"
options: array [
id: string (auto)
label: text, required // "DAY - Có màu"
+ image: upload → media // optional, for variant display
]
]
💡 The image field is available on ALL variant type options
But typically only the first type's options have images (like your screenshot shows "loại" options with images but "size" options without). The image field is optional so admins can leave it empty for types like "size".

How grouping works (data perspective)
// Variant doc stores options as [{typeId, optionId}, ...]
// First item = first variant type → used for grouping

variant_1.options[0].optionId → "o1" (DAY - Có màu)
variant_2.options[0].optionId → "o1" (DAY - Có màu)
// ↑ same first option = same group

variant_3.options[0].optionId → "o2" (NIGHT - Ko màu)
variant_4.options[0].optionId → "o2" (NIGHT - Ko màu)
// ↑ same first option = same group

// To get the image: look up product.variantTypeDefs[0].options
// find option where id === variant.options[0].optionId
// → option.image = the group image
✅ Does NOT break our approach
  • Image is just another field on the options array
  • Grouping is done by reading variant.options[0].optionId
  • No extra collections needed
  • Frontend reads image from product's inline data
📝 Gallery still coexists
  • Product gallery = main image carousel
  • Option image = variant group representative
  • Gallery variantOptionId can filter carousel by selected option
  • Both serve different UI purposes
